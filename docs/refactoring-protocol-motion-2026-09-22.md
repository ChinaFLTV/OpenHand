# 协议边界与导航动效重构

## 实施顺序

1. 确认 `main` 分支和干净工作区，建立静态分析基线。
2. 复核已有重构记录及共享并发、队列、缓存、文件操作、进程通信实现。
3. 对发现的协议和导航问题先复现，再修改生产代码并补充回归。
4. 执行全部现有检查入口、Web 重建、Rust 检查和 macOS 发布构建。
5. 复核差异，只提交本轮修改和重建产物，不推送。

## 改动

- 新增共享 JSON-RPC 响应信封识别，供 LSP、MCP JSON、流式 HTTP SSE、旧版 SSE 和标准输入输出通道复用。请求和响应编号相同也不能互相抢占；保留合法的空结果，拒绝同时携带结果和错误的矛盾信封。
- LSP 按原始编号匹配响应，移除小数编号截断；不支持的服务端请求返回方法不存在错误，通知不产生响应。
- LSP 在找到完整分隔符后仍检查消息头长度，堵住超长消息头绕过限制的路径。
- LSP 进程清理复用现有串行队列和统一资源移交入口，删除重复的 Future 串联、状态登记与进程摘除逻辑；保留重启、取消和关闭边界。
- Web 路由过渡超时或失败时完成导航，不再只清除动画标记。沿用代次隔离和一次提交机制，避免旧过渡覆盖新导航及迟到回调重复提交。
- 新增回归接入既有生命周期与 Web 交互检查入口，使用真实 Dart 子进程验证标准输入输出通信，不增加依赖。

响应识别依据：[JSON-RPC 2.0 响应对象规范](https://www.jsonrpc.org/specification#response_object)。这里只提取响应分类规则，业务结果继续由现有功能层解析。

## 复现与检查范围

- 修改前复现 LSP 同编号请求误收、小数编号误配、完整超长消息头漏检、MCP JSON 同编号请求误收；Web 过渡停滞导致导航丢失也已复现。
- 修复后的生命周期检查涵盖上述问题、MCP SSE 和标准输入输出响应隔离、启动取消后重启、重复停止，以及已有 CDP 和资源注册表行为。
- 复核统一弹窗和浮层入口、动效设置与退场控制、轮询及帧调度；本轮没有新建或重绘弹窗，没有更改现有弹性曲线和用户动画设置。
- 复核共享工具时保留已有有界并发、清理时限、文件恢复和缓存预算机制，避免重复建设。没有证据证明无用的业务文件或有效测试不删除。
- 内置 Prompt、数据库结构、原生 Rust 实现及依赖版本均未修改。

## 验收边界

这是基于现有架构的缺陷排查与重构，不等同于逐行证明全部业务组合无缺陷。当前主机为 macOS；Windows/Linux 实机、真实外部服务和账号组合仍需对应环境验收。未做帧率基准，不宣称未经测量的性能提升。

验收期间发现 `lib/features/mcp/widgets/mcp_view.dart` 和 `scripts/check_mcp_preview_widgets.dart` 出现外部变更，予以保留，不纳入本轮提交。上述回归结果对应各检查执行时的工作区。
