# 缓存、手势与构建回滚改进

## 检查与实施

1. 从干净工作区检查 Flutter、Web、Rust 结构和已有公共工具；Flutter 基线发现一处冗余默认参数。
2. 修复共享缓存预算、浮层登记和下拉刷新边界，复用现有回调、通知和数值工具。
3. 删除重复校验与说明，修复 Web 构建回滚失败后的备份丢失风险。
4. 执行回归检查、Web 重建及当前主机可用的桌面构建，复核后提交。

## 具体变更

- Dart LRU 在增加成本前按原访问顺序释放预算，避免整数溢出绕过限制。异步回填若淘汰自身，立即停止淘汰，不误删后续条目；保留空值缓存及身份检查语义。
- Web 文本缓存拒绝非有限数、负数、小数和不安全整数容量；零容量仍表示禁用缓存。
- Escape 栈为每次登记保留独立身份，同一对象重复登记时，注销旧登记不会删除新登记。
- 下拉刷新区分正常松手与取消，只接受所属触点、主触控笔；多指、空触点、捕获丢失、禁用和卸载取消未完成手势。同步刷新锁防止重复提交；失败释放忙碌状态并走现有通知，取消错误不弹通知。
- 手势局部状态随监听器释放；刷新回调复用 `useEventCallback`，避免每次渲染重新注册事件。阻尼指数统一为具名常量，删除重复的状态说明。
- 弹窗宽度复用已有尺寸校验，时长和数值归一化共用配置类型，移除会话列表显式声明的默认参数。
- Web 构建恢复失败时保留原产物备份并返回失败，避免静默删除唯一备份。

未修改内置 Prompt、依赖版本或视觉主题；弹窗继续使用现有全局动效入口。

## 验证

- `flutter analyze --no-pub`：无问题。
- `scripts/check_shared_helpers.dart`：通过，新增成本溢出、异步回填自淘汰和空值回归。
- LRU 与使用任意精度计数的参考模型对比：三个预算下共三万次随机操作通过。
- Web 运行时检查：通过，新增异常缓存容量及重复浮层登记回归。
- 手势检查：模拟 Hook 生命周期，直接驱动实际事件监听器，覆盖归属、取消、重复提交、重渲染、禁用、异常和卸载；已接入 `check:runtime`。
- 构建回滚故障注入：恢复成功、恢复失败保留备份、构建成功保留新产物，三条路径通过。
- `cargo test --workspace --locked --offline`：65 项测试通过。
- `scripts/build_web.sh`：通过，包含 TypeScript、运行时、架构、共享辅助、Web 引擎及产物检查。
- `flutter build macos --debug --no-pub`：通过。
- 桌面包内 Web 资源：195 个文件的清单和 SHA-256 与工作区一致。

## 验证边界

本轮实际修改和回归覆盖上述链路，不代表逐行验证了全部 836 个 Flutter 源文件。手势检查未替代真实触屏、触控笔及浏览器布局测试。Windows、Linux 完整桌面应用未在对应主机运行。macOS 仍提示三个既有插件尚未支持 Swift Package Manager，当前 CocoaPods 构建成功。
